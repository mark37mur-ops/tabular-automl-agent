# Полигон: тестовые задачи в формате кейса

Открытые датасеты, переупакованные так, как организаторы упаковали публичные задачи.
Формат — в [docs/data.md](../docs/data.md).

## Задачи

| Задача | Источник | Тип / метрика | Train / test | Бейзлайн | LightGBM по умолчанию |
|---|---|---|---|---|---|
| `amazon_access` | OpenML 4135 (Amazon Employee Access) | Бинарная / ROC AUC | 22 938 / 9 831, 9 признаков | 0.5207 | 0.8266 → 63.8 балла |
| `bike_sharing` | OpenML 42712 (Bike Sharing Demand) | Регрессия / RMSLE | 12 165 / 5 214, 12 признаков | 1.3011 | 0.4566 → 64.9 балла |
| `home_credit` | OpenML 45567 (Home Credit, основная таблица) | Бинарная / ROC AUC | 77 000 / 33 000, 120 признаков | 0.7298 | 0.7374 → 2.8 балла |

**Бейзлайн** — простая линейная модель: логистическая регрессия или Ridge, медианная
импутация, масштабирование и one-hot. Это наша оценка «самой простой модели», которую
бейзлайн-агент организаторов строит по своему промпту. Настоящий бейзлайн платформы
может отличаться, поэтому баллы ориентировочные.

Особенности, которые проверяет каждая задача:
- `amazon_access` — все признаки — высококардинальные ID категорий, записанные числами.
  Если считать их числовыми, модель почти случайна.
- `bike_sharing` — удалены `casual` и `registered`: они в сумме дают таргет (утечка).
  Редкая метрика RMSLE, мало строк.
- `home_credit` — 24% пропусков, аномалия `DAYS_EMPLOYED = 365243` у ~18% строк, дисбаланс 8%.
  Бейзлайн уже сильный, поэтому для баллов нужен заметный прирост.

## Использование

Скачанные данные (`raw/`) и собранные задачи (`tasks/`) не хранятся в git.

```bash
# 1. Скачать parquet с OpenML в polygon/raw/<id>/data.pq (повторы при 503)
python polygon/download.py

# 2. Собрать задачи (можно передать имена, чтобы собрать только их)
python -I polygon/build_tasks.py

# 3. Прогнать агента и посчитать балл
python agent/scripts/bench.py --tasks bike_sharing --time-limit 300

# Или оценить готовый ответ
python -I polygon/score.py home_credit path/to/submission.csv
```

Структура задачи:

```
tasks/<name>/public/   ← это отдаётся агенту
    task.md  train.csv  test.csv  data_dictionary.csv  sample_submission.csv
tasks/<name>/private/  ← агент это не видит
    answers.csv  meta.json (метрика, скор бейзлайна, ориентир LightGBM)
```

Формат `task.md` повторяет публичные задачи организаторов (функция `task_md` в `build_tasks.py`).

Имитации публичных задач (`wids_seen`, `wids_future`, `unsw_shift`, `unsw_covshift`) собирает
`build_derived.py` из файлов организаторов, которые в репозиторий не входят.
